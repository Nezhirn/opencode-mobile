# Исправления по код-ревью (стабильность, отзывчивость, UI)

Дата: 2026-10-03

Документ описывает правки по итогам глубокого код-ревью: что было не так, к чему это приводило и как исправлено. Безопасность в ревью не входила.

Проверка после правок:
- `./gradlew testDebugUnitTest` — 111 тестов, все зелёные (11 новых регрессионных);
- `./gradlew lintDebug` — 0 ошибок, новых предупреждений нет;
- на устройстве и эмуляторе приложение не запускалось, UI-правки проверены только сборкой.

---

## 1. Соединение и поток событий (`AppRepository`, `OpenCodeClient`)

| Проблема | Последствие | Исправление |
|---|---|---|
| Если `health()` при старте падал, начальная загрузка не повторялась; resync запускался только на повторных подключениях | После старта без сети приложение показывало «Подключено», но без сессий, моделей и агентов, пока пользователь не нажмёт Refresh | Полная синхронизация (`sync()`) запускается при **каждом** открытии потока, включая первое. Health больше не блокирует подключение и только обновляет версию сервера |
| Данные грузились **до** подписки на `/event` | События в этом промежутке терялись (`permission.asked` → чат вечно в Stop, а карточки нет) | Синхронизация стартует после открытия потока. `OpenCodeClient.events()` отдаёт синтетический `STREAM_OPENED_EVENT` из `onOpen` |
| Блокирующий `Call.execute()` не отменялся вместе с корутиной | Смена сервера ждала зависший запрос до 120 с, брошенные загрузки докачивались в фоне | `fetch()`: `enqueue` + `suspendCancellableCoroutine` + `call.cancel()`. Тело читается в колбэке OkHttp, поэтому отмена прерывает и скачивание. JSON декодируется на `Dispatchers.Default`. `maxRequestsPerHost` = 16 |
| При смене сервера данные старого оставались, а его фоновые загрузки писали в состояние нового | Сессии и карточки чужого сервера, ответы 404 | `clearServerData()` при смене `baseUrl`. Синхронизации живут в scope текущего клиента. Каждая `load*` проверяет `isCurrent(client)` |
| Поток, который ни разу не открылся, никогда не считался мёртвым | Вечное «Подключение…» на полуоткрытом сокете | `StreamHealth`: таймаут открытия 30 с |
| Backoff сбрасывался на любом событии | Поток, рвущийся сразу после открытия, перезагружал всё каждые 2 с | Backoff сбрасывается, только если поток прожил ≥ 30 с |
| SSE работал весь срок жизни процесса | Батарея и трафик в фоне, устаревший UI после возврата | `OpenCodeApplication.ForegroundTracker` → `AppRepository.setForeground()`. Через 30 с в фоне поток закрывается, при возврате открывается снова с полной синхронизацией |
| Снапшот `/permission` и `/question` затирал события, пришедшие во время запроса | «Мёртвые» карточки, на которые сервер отвечает ошибкой | Счётчики `permissionsEpoch`/`questionsEpoch`. Если во время запроса пришло событие, снапшот перечитывается (`loadSnapshot`, до 3 попыток) |
| `retryOnConnectionFailure(true)` повторял POST | Возможен двойной запуск промпта | Для запросов, отличных от GET, используется клиент без повтора |
| В баннер ошибки попадало всё тело ответа | HTML-страница прокси на весь экран | `extractError`: HTML отбрасывается, текст обрезается до 300 символов |
| `session.updated` не пересортировывал список | Активная сессия не поднималась наверх | Список пересортировывается по `time.updated` |

## 2. Чат (`ChatController`, `ChatModels`, `ChatViewModel`, `ChatScreen`, `ChatPanels`, `ChatInputBar`)

| Проблема | Последствие | Исправление |
|---|---|---|
| Снапшот `load()` целиком заменял сообщения | Промпт, отправленный во время загрузки, исчезал; в середине стрима появлялись «дыры» | `withMessagesIfCurrent(…, knownBefore)` сливает снапшот с живым состоянием: <br>• новые сообщения сохраняются; <br>• если живой текст части длиннее, остаётся он; <br>• удалённые на сервере сообщения уходят |
| После resync локальное эхо дублировало серверное сообщение | Промпт показывался дважды, следующие промпты занимали чужое эхо | Эхо отбрасывается, если в снапшоте есть ещё не известное user-сообщение с тем же текстом |
| Гонка таймерного `flushDeltas` и `message.part.updated` | Хвост ответа удваивался | Буфер дельт забирается и применяется под одним `deltaLock`. `part.updated` и применение снапшота делаются под ним же |
| `session.error` сабагента сбрасывал busy родителя | Stop пропадал посреди работы | Busy сбрасывает только ошибка собственного прогона чата. Ошибка сабагента только показывается |
| `todo.updated` сабагента заменял список задач родителя | Неверный TodoStrip | Строгое сравнение `sessionID` |
| Обработчики событий писали через `update` без привязки к сессии | Событие могло попасть в только что открытый чат | `targetOf()` + `updateIfCurrent(target)` во всех обработчиках |
| Повторное быстрое открытие той же сессии очищало чат | Пустой чат без повторной загрузки | Владелец чата: `open(…, owner)` и `close(…, owner)`. Закрыть чат может только последний открывший его экран |
| Черновик целиком писался в `SavedStateHandle` | Краш `TransactionTooLargeException` при уходе в фон с большим вставленным текстом | Черновик хранится в памяти, в saved state попадает только до 50 000 символов |
| Двойной нижний отступ над клавиатурой | Пустая полоса около 48dp | `consumeWindowInsets(padding)` перед `imePadding()` |
| Автоскролл не срабатывал при сжатии области списка | Конец чата уходил под клавиатуру или панель разрешений | Отдельный эффект по высоте viewport |
| Первая эмиссия `snapshotFlow` сбрасывала сохранённый `follow` | Прыжок в конец после возврата на экран | `.drop(1)` |
| Бюджет панелей не учитывал поле ввода | В landscape с клавиатурой поле ввода обрезалось | Высота `InputBar` (через `onSizeChanged`) вычитается из бюджета |
| Ошибку чата нельзя было закрыть | Красная строка висела до следующей отправки | Кнопка «Закрыть» + `clearChatError()` |
| Ответы в QuestionCard хранились в `remember` | Терялись при split-screen, смене шрифта или языка | `rememberSaveable` с собственными `Saver` |
| — | — | `contentType` у элементов `LazyColumn` |

## 3. Markdown и большие тексты (`Markdown`, `MarkdownText`, `TruncatedText`)

| Проблема | Последствие | Исправление |
|---|---|---|
| Любая ссылка становилась `LinkAnnotation.Url` | Тап по `file://` ронял приложение (`FileUriExposedException`) | Кликабельны только `http`, `https`, `mailto` (`isOpenableLink`). Плюс `SafeUriHandler`, который ловит исключения |
| Полный разбор Markdown на main-потоке каждые 50 мс стрима | Jank на длинных ответах | `rememberMarkdownBlocks`: разбор на `Dispatchers.Default`, промежуточные версии текста схлопываются через `conflate`, разбор не перезапускается. LRU-кэш `MarkdownCache` до 1 млн символов |
| Абзац без пустых строк был одним `Text` | Огромный `TextLayout` перекладывался на каждый токен | `addParagraph` режет длинный абзац по переводам строк, стили сохраняются |
| Вложенность цитат, списков и выделений не ограничена | Текст нулевой ширины; `StackOverflowError`, в том числе внутри самого commonmark | `MAX_NESTING` = 8 (глубже содержимое разворачивается итеративно), `MAX_INLINE_DEPTH` = 32, фолбэк на простой текст при `StackOverflowError`, отступ на экране ≤ 6 уровней |
| Ячейка таблицы без ограничения ширины | Краш раскладки на очень широкой ячейке | Текст ячейки до 500 символов, `widthIn(max = 480.dp)`, многоточие |
| Маркер списка переносился в колонке 20dp | «100.» ломался на две строки | `softWrap = false`, `widthIn(min)` |
| Чанк, оканчивающийся на `\n`, рисовался отдельным `Text` | Лишняя пустая строка каждые ~2000 символов в коде, диффах и файлах | `chunkForDisplay()` убирает завершающий перевод строки |
| `chunkedForLayout` искал перевод строки по всей строке назад | O(n²) на тексте без переводов строк | `chunkEnds()` ищет только в пределах текущего чанка |
| Текст длиннее 200 000 символов обрезался молча | Не было видно, что текст неполный | Пометка `text_truncated` (plurals) |

## 4. Экраны, навигация, настройки

| Проблема | Последствие | Исправление |
|---|---|---|
| Нет корневого `Surface` | В тёмной теме текст ConnectScreen был чёрным на тёмном фоне | `MainActivity`: `Surface(color = background)` вокруг `AppRoot` |
| `popBackStack()` без проверки | Быстрый двойной «назад» оставлял пустой экран | `popIfCurrent(entry)` |
| Пароль формы подключения хранился в `remember` | Терялся при смене языка, сохранялся пустой → 401 | Форма перенесена в `ConnectViewModel` |
| ConnectScreen без системных отступов, `imePadding` стоял после скролла | Контент заходил под статус-бар, навбар и клавиатуру | `safeDrawingPadding()` перед `verticalScroll` |
| Ошибка чтения DataStore уходила в scope репозитория | Повреждённый файл ронял приложение при каждом запуске | `ReplaceFileCorruptionHandler` + `.catch { IOException → emptyPreferences() }` |
| Шифрование Keystore выполнялось внутри `edit {}` на main-потоке | Фриз при первом сохранении | `encrypt` на `Dispatchers.Default` до `edit` |
| Нерасшифровываемый `v1:` пароль подставлялся в поле | Шифротекст пересохранялся как «пароль» | Такой пароль читается как пустой |
| Выбор модели хранился глобально | Переключение между серверами стирало выбор | Выбор хранится для каждого сервера (`selected_*@<url>`, со старыми ключами как запасным вариантом). `SelectionStore` перечитывает его при смене сервера. Записи сериализованы через `Mutex` |
| Список сессий пуст до загрузки | Ложное «Сессий нет» | `sessionsLoaded`, индикатор загрузки, отдельный текст «Ничего не найдено» для поиска, ошибка загрузки показывается в баннере |
| «Файлы» без сессии не грузили VCS | «Рабочее дерево чистое» при наличии изменений | `FilesViewModel.load(null)` грузит VCS. Вкладка «Изменения» без сессии скрыта. Есть индикаторы загрузки |
| Ошибка листинга папки показывала «Пустая папка» и меняла путь | Ошибка выглядела как пустая папка | При ошибке остаёмся в прежней папке, ошибка показывается в баннере |
| Системный «назад» в подпапке закрывал экран | Терялась позиция в дереве файлов | `BackHandler` поднимается на уровень выше |
| `openDirectory("")` повторялся при пересоздании Activity | Сброс в корень | Однократная инициализация в VM |
| `SessionsViewModel.init` перезапускал поток | Лишнее переподключение при старте | Убрано: синхронизация происходит при открытии потока |

## 7. Изменения поведения, о которых стоит знать

- Ссылки на относительные пути и `file://` в ответах показываются обычным текстом.
- Через 30 с в фоне поток событий закрывается. Если генерация завершится, пока приложение в фоне, это будет видно после возврата.
- При копировании выделения через границу чанка (каждые ~2000 символов) теряется один перевод строки. Это цена за исправление лишних пустых строк.
- Вкладка «Изменения» в «Файлах» видна только при открытой сессии.

## 8. Что осталось

- Тела больших ответов (`/file/content`, история сообщений) по-прежнему читаются в память целиком. Декодирование уже вынесено с main-потока.
- Сообщение ассистента остаётся одним элементом `LazyColumn` (добавлен только `contentType`). Части сообщения стоит развернуть в отдельные элементы, если на длинных прогонах агента останется jank.
- Нужна проверка на устройстве: insets, автоскролл, тёмная тема, поведение при уходе в фон и возврате.
